## Project Summary
Evidence of using Cursor to organize AI Operations portfolio documentation, refine workflow docs, and iteratively improve materials with structured prompts and review.

## Business Problem
Building a truthful, recruiter-ready AI Operations portfolio requires organized documentation, consistent process language, repeated revision, and quality control across resumes, project case studies, interview stories, and evidence packs. Cursor supports faster, more structured AI-assisted drafting and refinement while keeping human ownership of accuracy.

## My Responsibilities
- Used Cursor to develop and organize AI Operations portfolio documentation
- Directed AI-assisted drafting for resumes, project overviews, interview stories, and strategy docs
- Reviewed outputs for truthfulness, removed unsupported claims, and enforced accuracy standards
- Iteratively refined prompts/instructions to improve document quality and consistency
- Structured folders and evidence templates for employer-ready presentation

## Workflow Design
Typical Cursor-assisted documentation workflow:
1. Define document goal and constraints (truthful only, no invented metrics)
2. Provide source context from real projects
3. Generate structured draft
4. Human review for accuracy and ATS quality
5. Refine with follow-up instructions
6. Finalize into portfolio files

## Prompt Engineering
- Wrote clear instructions for document structure, tone, and constraints
- Required sections for business problem, testing, QA, root cause analysis, and transferable skills
- Iteratively refined prompts when drafts overclaimed or drifted from real experience
- Used constraint-based prompting to keep content recruiter-ready and truthful

## Testing Methodology
- Review each generated section against known real experience
- Check for invented employers, dates, certifications, metrics, or deployments
- Validate keyword relevance for target AI roles
- Revise and re-check until claims remain supportable

## Root Cause Analysis
When draft quality failed, identify whether the issue was:
- Ambiguous instructions
- Missing source context
- Overly broad role targeting
- Insufficient truthfulness constraints
- Weak structure requirements

## Quality Assurance Process
Instruction → draft → accuracy review → constraint reinforcement → revision → final acceptance

## Debugging / Issue Tracking (Documentation QA)
Issues were treated like documentation defects:
- Spot unsupported claim
- Classify cause (prompt, missing context, weak constraint)
- Fix instruction or content
- Re-check the section
- Keep only supportable statements

## Lessons Learned
- AI-assisted documentation still requires strict human QA
- Clear constraints prevent overclaiming
- Structured templates improve consistency across an AI Operations portfolio
- Iterative prompting is a practical Prompt Engineering Support skill
